# Frontend development

The frontend is a React and TypeScript application under `frontend/`.

## Project structure

- `src/App.tsx` configures TanStack Router, React Query, Material UI, dates, and toast notifications.
- `src/routes/` contains file-based routes and route loaders.
- `src/features/` groups components and state by application feature.
- `src/components/` contains reusable components.
- `src/api/` contains request helpers, response types, and query or mutation definitions.
- `src/hooks/` contains shared React hooks.
- `src/theme.tsx` defines the Material UI theme.
- `src/routeTree.gen.ts` is generated by the TanStack Router plugin.

The `@` import alias resolves to `frontend/src`.

## Routes

TanStack Router generates the route tree from files under `src/routes/`. Route groups distinguish public pages, public-only pages such as login, and authenticated pages. Private routes check the allauth session and redirect unauthenticated users to `/login`.

Do not manually edit `src/routeTree.gen.ts`. The router plugin regenerates it when route files change.

## Server data

TanStack Query manages remote data. Shared query options and mutations live primarily in `src/api/queryOptions.tsx`; transport helpers and TypeScript contracts live elsewhere under `src/api/`.

When changing an API contract:

1. Update the backend serializer and tests.
2. Update the matching frontend type.
3. Update query or mutation behavior.
4. Confirm affected query keys are invalidated after mutations.

Use `VITE_API_URL` for `/api/` endpoints and `VITE_BACKEND_URL` for django-allauth endpoints. See [Local development](1-local-development.md#frontend-setup).

## Common commands

Run these from `frontend/`:

```sh
npm run dev
npm run lint
npm run format
npm run build
npm run preview
```

`npm run build` runs the TypeScript project build before creating the Vite production bundle in `frontend/dist/`.

## UI conventions

Use Material UI components and the shared theme before introducing custom primitives. Place feature-specific code in the relevant `features` directory and reusable code in `components`, `hooks`, or `utils`. Keep API access in `src/api` rather than embedding fetch logic throughout components.
